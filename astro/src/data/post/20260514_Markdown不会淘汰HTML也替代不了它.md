> **本文背景**：Claude Code 工程师 Thariq 在 X 上发了一篇长文，讨论 AI 时代为什么 HTML 比 Markdown 更好。这篇帖子获得了超过 1200 万次阅读，引发了技术社区的广泛讨论。本文是我对这个话题的完整回应。

## 01. 一个引发广泛讨论的话题

最近，Claude Code 工程师 Thariq 在 X 上发了一篇长文，标题叫《Using Claude Code: The Unreasonable Effectiveness of HTML》。这篇帖子获得了超过 1200 万次阅读，引发了技术社区的广泛讨论。

帖子的大意是：AI 时代，HTML 比 Markdown 更好。

他给出了四个理由：

第一，信息密度更高。HTML 可以嵌入表格、图表、动画、交互元素。AI 给你的一份文档，不再是干巴巴的文字，而是有图、有动画、有按钮的"多媒体"。

第二，视觉上更容易读。超过一百行的 Markdown 文件，很少有人能认真读完。但 HTML 可以用布局、颜色、字体来组织信息，让眼睛更容易找到重点。

第三，分享更容易。Markdown 文件在浏览器里打开就是一堆符号。HTML 上传到网络就是一个链接，点开就能看，微信里直接转发，接收者不需要任何特殊软件。

第四，可以双向交互。他可以让 AI 生成一个带有滑动条和按钮的 HTML 页面，调整参数满意了，再把参数复制回 AI 继续工作。这个，Markdown 完全做不到。

听起来很有道理，对不对？

但我要告诉你：Markdown 作为知识存储的基础工具，它的价值不仅没有过时，反而在 AI 时代变得更加重要。

我的核心观点是：

Markdown 是地基，HTML 是地面上的建筑。地基要稳，建筑要好看。两者不是替代关系，是分层关系。

## 02. 最重要的一个问题：谁来读这份文件？

在讨论"用哪个格式"之前，我们需要先问一个问题：

这份文件最终是谁来消费的？

这里有两种完全不同的消费者：

消费者 A：机器。包括 AI 模型、搜索系统、代码。你的知识能不能被 AI 理解、能不能被检索、能不能被版本控制——这是机器消费的核心需求。

消费者 B：人。包括你自己、你的同事、你的读者。你的知识能不能让人一眼看懂、能不能方便分享、能不能形成记忆——这是人类消费的核心需求。

Markdown 和 HTML 在这两个维度上的表现，截然不同：

第一维度 Markdown，特性是 AI 读取效率高，因为它是纯文本，没有标签噪音。HTML 在这个维度表现一般，因为标签对 AI 来说是噪音。

第二维度人类视觉体验，Markdown 受限于格式能力，表现一般。HTML 则表现好，可以嵌入任意视觉元素。

第三维度分享便捷度，Markdown 需要专用软件才能有好的渲染体验，表现较差。HTML 浏览器直接打开就能看，表现好。

第四维度版本控制，Markdown 表现好，diff 就是文本对比。HTML 表现差，标签噪音会淹没内容。

第五维度 RAG 检索，Markdown 语义清晰，表现好。HTML 表现差，因为需要过滤大量标签噪音。

所以问题不是"哪个更好"，而是"你的场景更需要谁"。

这才是这场争论的真正核心。

## 03. 知识的生命周期：创作 → 整理 → 传播 → 归档

理解了"谁来消费"，我们再来看一份知识从诞生到消亡会经历哪些阶段。

我把知识分成四个阶段：

第一阶段：创作。你有一个想法，把它写下来。这个阶段的核心是写得快、写得顺，不需要操心格式。Markdown 在这个阶段的优势是极致的——你专注在内容上，`# 标题` 就是标题，`[[双向链接]]` 就能建立知识关联。

第二阶段：整理。你写完初稿，需要归档、建立关联、反复修改。这个阶段 Markdown 的版本控制能力就派上用场了。每次修改都有记录，任何时候都能回退，两个人的改动可以合并，冲突可以高亮。Word 和 PDF 做不到这一点——它们的格式是锁定的，版本管理基本靠"文件名加日期"。

第三阶段：传播。你的知识需要分享给更多人。这个时候 HTML 的主场就到了。一份报告、一个分享页面、一个可以交互的演示——HTML 可以直接上传网络生成链接，接收者用浏览器直接打开就能看到完整的视觉效果。

第四阶段：归档。你的知识成为一份正式的、被引用的记录。PDF（便携文档格式）是最好的选择，因为它的版式是固定的、不可篡改的，适合作为"最终版"存档。

## 04. 文本格式大比拼：TXT / Word / PDF / Markdown

现在让我们把主流的文本存储格式逐个分析一遍。

TXT：临时工的命

优点：任何设备都认识，没有任何兼容问题，几乎零成本。

缺点：没有任何结构。标题和正文一样，表格和普通文字一样。机器读不出语义，人读也找不着重点。

一句话：TXT 适合临时记录，不适合知识管理。

Word（.docx）：专有格式的代价

Word 是最常见的"正式文档"格式，但作为存储格式，它的问题很多。

最大的问题是版本控制几乎不可能。docx 本质上是一个压缩的二进制文件，Git 只能看到"文件变了"，但看不到"哪里变了"。你没法精确看到文档里每一行的修改记录。

其次是格式依赖软件。Word 文件需要 Microsoft Word 才能正常打开，苹果用户经常遇到格式错位的问题。

第三是 AI 读取困难。AI 处理 Word 文档时，需要解析 docx 的二进制结构，这个过程会引入噪音。

一句话：Word 适合协作编辑，但代价是版本控制和 AI 可读性。

PDF：只读的，死的

PDF（便携文档格式）的设计目标是"所见即所得"——任何设备上看，版式都一样。

优点是不可篡改，适合正式发布和归档。

但致命的问题是：完全不可编辑。PDF 只能看，不能改。如果你想基于一份 PDF 做二次创作，你只能从头复制粘贴。

一句话：PDF 适合归档，不适合需要迭代的知识管理。

Markdown：平衡的胜出者

Markdown 为什么最终成为知识管理的主流选择？

因为它在几个关键维度上都没有致命弱点：

AI 读取无压力——纯文本，AI 直接理解内容，不需要解析标签。版本控制友好——Git diff 就是字面意义的文本对比。格式简单但有效——覆盖了 90% 的日常需求。工具链成熟——Obsidian、Logseq、Typora，大量工具支持。

更重要的是：Markdown 文件本身就是一种 API（应用程序接口）。你的电脑、你的 AI 工具、你的搜索系统，它们都原生理解纯文本。你可以 grep 搜索，可以写脚本处理，可以用任何编程语言读取。

一句话：Markdown 是知识管理的"万能底座"——不是最强的，但恰好没有致命弱点。

## 05. 演示格式：为什么 PPT 正在被淘汰？

说完文本格式，我想花一点时间聊演示格式。这个和 HTML 的讨论高度相关。

先看 PPT 和 HTML 的对比。

PPT 的三个致命问题

第一，制作成本极高。以前做一个像样的 PPT，需要设计师、动画师、排版人员——整个团队。

第二，跨平台兼容性差。PPT 文件在不同软件、不同系统上打开，经常有格式错位的问题。

第三，无法和 AI 工作流集成。你没法用 prompt 来"生成一页 PPT"，因为 PPT 的格式是封闭的。

HTML 的优势

HTML 加上 CSS 和 JavaScript，可以实现 PPT 能实现的一切，而且成本更低：

AI 可以直接生成——一个 prompt，Claude 就能给你一个完整的 HTML 演示页面。跨平台天然——任何设备、任何浏览器都能直接打开。动画制作简单——CSS animation 比 PPT 的动画窗格简单十倍。分享成本趋近于零——上传到静态服务器，生成链接，直接分享。

所以我的判断是：PPT 作为工具正在被淘汰，不是演示本身被淘汰。

演示的本质——分页叙事、视觉辅助、结构化表达——依然有效。但制作工具从专有软件变成了 HTML + AI。这个转变是不可逆的。

## 06. 核心论点：分层架构

好了，讲了这么多铺垫，现在让我把核心论点说出来。

我的核心论点是：

Markdown 应当作为知识存储的基础层，HTML 和其他格式是建立在它之上的展示层。

这不是一个非此即彼的选择，而是一个分层架构。

```
┌─────────────────────────────────────────┐
│           展示层（输出）                  │
│   HTML（传播）  /  PDF（归档）            │
├─────────────────────────────────────────┤
│           核心层（存储）                  │
│         Markdown（源文件）               │
└─────────────────────────────────────────┘

解释：
- Markdown 是源文件，是"地基"
- HTML 是传播用的"地上建筑"
- PDF 是归档用的"地下室"
- 三者并存，不是否定关系
```

为什么 Markdown 是地基？

三个原因：

第一，稳定性。20 年前的 Markdown 文件，今天的任意设备都能打开。2004 年的 HTML 页面，今天可能已经因为浏览器兼容性问题无法正常显示。Markdown 的持久性远超其他格式。

第二，AI 可读性。AI（人工智能）读取 Markdown 时，不会被标签噪音干扰。AI 看到的是内容本身，不是大量的 `<div>` 和 `class`。

第三，版本控制友好。每次修改都有清晰的 diff，你知道"这周改了什么"。这个特性对于知识积累和追溯至关重要。

而 HTML 的价值在于展示层：当你需要分享、需要可视化、需要交互时，HTML 提供 Markdown 无法提供的视觉表达能力和互动能力。

PDF 的价值在于归档层：当你需要一份不可篡改的正式记录时，PDF（便携文档格式）是最安全的选择。

## 07. Thariq 的论点错在哪里？

现在我可以回应 Thariq 的原帖了。

他的核心论点是：在 AI（人工智能）协作场景下，Markdown 的局限性太大了，HTML 是更好的选择。

他的论据我不反驳——他描述的 HTML 的优势是真实的。

但他犯了一个根本性的错误：他只看到了展示层，忽视了存储层。

他的所有论据都是从"人读"的角度出发的：更易读、更易分享、更有视觉冲击力。

但他完全没有考虑这份知识从哪里来。它如何被索引和检索。版本控制怎么做。AI（人工智能）怎么读取其中的语义。

这些问题的答案都是 Markdown，而不是 HTML。

更重要的是：Thariq 的使用场景是一个特殊场景——在他的工作流里，AI（人工智能）是主要的输入者，人类主要是消费者。

这种场景下，HTML 确实是更好的输出格式。

但这不代表 Markdown 不好。这只代表：不同的场景需要不同的格式。

如果我们把视角从"AI（人工智能）写给人读"扩展到"人类创作、存储、传播、归档的全生命周期"，Markdown 作为存储层的价值是无可替代的。

## 08. 一个完整的工作流

最后让我用一个具体的例子说明这套框架如何落地。

假设你要做一个知识库来沉淀你读过的书。

第一步：读书笔记用 Markdown 记录。

读到有意思的章节，用 Markdown 写笔记。每条笔记包含：你理解的核心观点、原文摘录、你的联想。将这些笔记存在 Obsidian 里，用双向链接把相关的笔记关联起来。

第二步：重点章节用 HTML 做成分享内容。

你觉得"知识的诅咒"这个概念很值得做成一期短视频，于是让 AI（人工智能）把 Markdown 笔记转换成 HTML 页面，加入图表、动画，让它更容易被观众理解。HTML 页面分享出去，粉丝点开链接就能看到精美的内容。

第三步：如果内容特别好，做成 PDF（便携文档格式）归档。

这期视频反响很好，你决定把它扩展成一本电子书。Markdown 的内容被导出为 PDF，成为一份正式的、可被引用的出版物。

整个过程中，Markdown 文件始终在你的知识库里。它是你可以随时搜索、修改、迭代的源文件。HTML 和 PDF（便携文档格式）只是面向不同场景的不同视图。

这个 workflow 最大的价值不是让你多存几个文件，而是让你的知识活起来。

## 结论

回到最开始的问题：Markdown 还是 HTML？

我的答案是：这不是一个"哪个更好"的问题，而是一个"哪个更适合当前场景"的问题。

如果你的场景是知识存储、版本控制、AI（人工智能）读取、RAG（检索增强生成）检索——Markdown 是基础层的最佳选择。

如果你的场景是人际传播、可视化展示、交互式内容——HTML 是展示层的最佳选择。

如果你的场景是正式归档、不可篡改——PDF（便携文档格式）是归档层的最佳选择。

格式不是目的，知识的存储、传递、传承才是目的。选择工具，让工具为你服务，而不是被工具绑架。
